#+TITLE: Refactor — Enemy Weapon Architecture Phase 1: Data Layer
#+STATUS: READY FOR AEF

* Why

=EnemyResource= encodes its weapon as a raw inline Dictionary
(={"attribute": "str", "die": 6, "proficiency_bonus": 2}=) with
=parry_bonus=, =block_value=, and =block_die= bolted on as three
separate top-level fields.  Party weapons, by contrast, live in
typed =WeaponResource= =.tres= files (=data/weapons/=) loaded by path.
The result is two completely different weapon models for enemies and
party members, which means:

1. The same weapon stats (arming sword, spear, shortbow) cannot be
   shared between an enemy and a party member — each enemy type
   hard-codes its own untyped dict.
2. Giving two skeletons different weapons (one arming-sword, one
   spear) requires copying the entire =skeleton.tres= file; there is
   no per-spawn override mechanism.
3. The three top-level parry/block fields on =EnemyResource= are
   architecturally wrong — in the source material those properties
   belong to the *weapon*, not the creature.

Goal: give enemies the same weapon model as party members.  Each
=EnemyResource= stores an Array of =res://= paths to =WeaponResource=
=.tres= files.  =EncounterResource= gains a parallel
=weapon_path_overrides= Array so individual spawn slots can carry a
different weapon than the =.tres= default, without any new enemy file.

Phase 1 is the *data layer only*.  The reaction system
(=trigger["weapon"]=, =_compute_legal_reactions=, =legal_reactions=
format, the reaction prompt UI) is explicitly *unchanged* — the
backward-compatible =weapon= field on the =Combatant= entity insulates
all reaction tests from this refactor.  Phase 2 (per-weapon reaction
options, multi-weapon chooser) is a separate run.

* Current state (verified 2026-08-10)

- =data/enemies/enemy_resource.gd= — =@export var weapon: Dictionary
  = {}= (keys: =die=, =proficiency_bonus=, =attribute=) plus three
  separate top-level fields: =@export var parry_bonus: int = 0=,
  =@export var block_value: int = 0=, =@export var block_die: int = 0=.
- =data/enemies/skeleton.tres= — =weapon = {"attribute": "str", "die":
  6, "proficiency_bonus": 2}=; =parry_bonus = 4=; =block_value = 2=;
  =block_die = 0=.
- =data/weapons/arming_sword.tres= — does NOT exist yet.
- =data/encounters/encounter_resource.gd= — no weapon override field.
- =infrastructure/combatant_factory.gd= — reads =enemy.weapon= dict
  and =enemy.parry_bonus/block_value/block_die= separately to assemble
  the combatant =weapon= dict.
- =core/domain/combatant.gd= — single =var weapon: Dictionary = {}=
  field; no =weapons= array.
- GUT baseline: 3556 passing, 0 failing, exit 0.

* Non-goals (Phase 1)

- Phase 2 reaction expansion: =trigger["weapons"]= array, per-weapon
  =legal_reactions= option objects, =_compute_legal_reactions=
  per-weapon enumeration, reaction prompt weapon labels — ALL deferred.
- Shield =.tres= files (=small_shield=, =large_shield=, =buckler=) —
  needed for Phase 2 multi-weapon enemies; deferred.
- =off_hand_path_overrides= on =EncounterResource= — deferred; Phase 1
  adds only the primary weapon override.
- PC shield block stats (=Patience='s shield =ItemResource= carries no
  block/parry values) — a related but separate gap.
- Strike-verb weapon selection (choosing which equipped weapon to attack
  with) — Phase 2 or later.
- Any change to =core/application/reaction_window.gd=,
  =round_session.gd= trigger builders, or the =legal_reactions= string
  format.

** EWA-4 — =CombatantFactory= enemy build path

*** EWA-4-0  =infrastructure/combatant_factory.gd= — =build_enemy_combatant()=

Add an optional fourth parameter to =build_enemy_combatant()=:

#+BEGIN_SRC gdscript
func build_enemy_combatant(
    enemy_path: String,
    hex_coord,
    combatant_id: String = "",
    weapon_path_override: String = ""
) -> Dictionary:
#+END_SRC

Replace the body's weapon-resolution logic:

*Old logic (remove entirely):*
- Read =enemy.weapon= dict for =die=, =proficiency_bonus=, =attribute=.
- Read =enemy.parry_bonus=, =enemy.block_value=, =enemy.block_die= as
  top-level fields.
- Validate each field with typed error returns.

*New logic:*
1. Determine the weapon path: if =weapon_path_override != ""= use it;
   otherwise if =enemy.weapon_paths= is non-empty use =enemy.weapon_paths[0]=;
   otherwise return =_fail_enemy_resource_load(ERR_ENEMY_RESOURCE_WEAPON_UNRESOLVABLE,
   "weapon_paths is empty — no weapon configured for this enemy", enemy_path)=.
2. Load a =WeaponResource= via =ResourceLoader.load(resolved_weapon_path)=.
   If null: return =_fail_enemy_resource_load(ERR_ENEMY_RESOURCE_LOAD_FAILED,
   "weapon WeaponResource failed to load from '%s'" % resolved_weapon_path,
   enemy_path)=.
3. Validate the loaded =WeaponResource= fields using the same
   non-negative checks as before (=damage_die >= 0=,
   =proficiency_bonus >= 0=, =parry_bonus >= 0=, =block_value >= 0=,
   =block_die >= 0=), returning =ERR_ENEMY_RESOURCE_INVALID_WEAPON_FIELD=
   on failure.
4. Build the combatant =weapon= dict from =WeaponResource= fields
   (identical shape to current output): =damage_modifier_attribute=
   (from =weapon_res.damage_modifier_attribute= directly — no =attribute_map=
   translation needed since =WeaponResource= already stores full attribute
   names like ="strength"=), =proficiency_bonus=, =damage_die=,
   =parry_bonus=, =block_value=, =block_die=.
5. Also populate =weapons= Array on the combatant dict (see EWA-5):
   =combatant["weapons"] = [combatant["weapon"].duplicate(true)]=.

The =attribute_map= translation step (={"str": "strength", "dex":
"dexterity"}=) is removed — =WeaponResource.damage_modifier_attribute=
already stores the full attribute name (="strength"=, ="dexterity"=),
unlike the old inline dict's =attribute= key which stored the short
form.

Call-site update: wherever =build_enemy_combatant(enemy_path,
hex_coord, combatant_id)= is called and an =EncounterResource= is
available, pass the relevant =weapon_path_overrides= entry as the
fourth argument:

#+BEGIN_SRC gdscript
var override: String = ""
if encounter_res.weapon_path_overrides.size() > i:
    override = encounter_res.weapon_path_overrides[i]
var result = _combatant_factory.build_enemy_combatant(
    enemy_path, hex_coord, combatant_id, override
)
#+END_SRC

** EWA-5 — =Combatant= entity: =weapons= Array and backward-compat alias

*** EWA-5-0  =core/domain/combatant.gd= — add =weapons= field, keep =weapon=

Add one new field:

#+BEGIN_SRC gdscript
## All equipped weapons as an Array of weapon dicts (same dict shape

  =weapons= is always a non-empty Array when =weapon= is non-empty, so
  Phase 2 code can safely read =weapons[0]= without a nil guard.

=to_dict()= changes:
- Add ="weapons": weapons.map(func(w): return w.duplicate(true))= to
  the returned Dictionary.  Existing ="weapon"= key is unchanged.
