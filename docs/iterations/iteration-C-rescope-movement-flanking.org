* THE ONLY COMMITTED SCOPE FOR THIS SPRINT (all P0 / MUST)

Domain-first (ADR-001: all positioning/reach/flanking logic in core/, zero Node/
Control; UI only reads/derives). Reuse existing ports/use-cases (ADR-002); the only
new domain code is the movement/flanking logic below. All GUT-tested.

1. Hex coordinate model + pure utilities (FR-011): flat-top hex grid, 1 hex = 5 ft,
   6-neighbour adjacency, NO diagonal cost. Pure hex-distance and adjacency
   functions usable by movement, reach, and flanking.
2. Step (FR-012): move exactly 1 hex as a FREE action (no action-economy cost),
   to an unoccupied adjacent hex.
3. Stride (FR-013): move up to the combatant's Speed (4 hexes) along adjacent hexes;
   COSTS one action per the existing action economy / Movement trait; may not exceed
   Speed; may not end on an occupied hex.
4. Reach re-gating: after a Step or Stride, recompute reach eligibility before
   allowing a Strike. Melee reach = adjacency (6 neighbours); ranged = listed range
   in hexes.
5. Flanking → Off-Guard (FR-016): when an attacker and an ally occupy directly-
   OPPOSITE adjacent hexes relative to a target, the target is Off-Guard (blanket
   +2 to attacks against it) while so positioned; integrate into attack resolution.
   v0 is blanket (NOT flankers-only — that tightening is a documented future lever).
6. UI wiring for the above: interactive Step/Stride input on the player's turn
   (select destination hex within budget), visual reach/flank affordances derived
   from the domain state. Extend existing controls; do not rebuild them.
