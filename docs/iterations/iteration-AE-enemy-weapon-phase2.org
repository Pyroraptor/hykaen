#+TITLE: Iteration AE — Enemy Weapon Architecture Phase 2: Off-Hand Weapons & Reaction Enrichment
#+SPRINT: 44
#+VERSION: 0.2.5

* Goal

Give combatants equipped with a shield (or any off-hand weapon) richer,
weapon-aware reaction options.  When Patience (mace + small shield) is
targeted by an enemy Strike, the reaction prompt should show
"Block (Small Shield 1d10+4)" — using the shield's dedicated block die —
rather than a plain "Block" backed by the mace's weaker block stats.
Enemy AI likewise uses the best eligible weapon per reaction type.

This is the continuation of the Phase 1 data-layer refactor
(=docs/refactors/enemy-weapon-architecture-phase1.org=).  Phase 1 moved
=EnemyResource= to =weapon_paths=, gave =Combatant= a =weapons: Array=
field, and wired =EncounterResource.weapon_path_overrides= for per-slot
primary weapon overrides.  Phase 2 populates =weapons[1]= with off-hand
weapons and wires the full array into the trigger, eligibility, and UI
layers.

* Current state (verified 2026-08-11)

- =Combatant.weapons: Array= exists (Phase 1 EWA-5) but contains exactly
  one element — =weapons[0]= mirrors the primary =weapon= dict.
- =build_party_combatant()= scans =character.starting_equipment= for the
  FIRST =WeaponResource=; Patience's =starting_equipment= has
  =["res://data/weapons/mace.tres", "res://data/armor/chain_shirt.tres"]=

  metadata only) with no weapon stats.
- No shield =WeaponResource= =.tres= files exist yet.
- =EncounterResource= has =weapon_path_overrides: Array[String]= (Phase 1)
  but no =off_hand_path_overrides= field.

  no off-hand path support.
- =trigger["weapon"]= = =target.weapon= (primary only); no ="weapons"= key

* Non-goals

- Changing the =legal_reactions: Array[String]= contract — it stays bare
  strings (="parry"=, ="block"=, …).  No option dicts, no namespaced
  strings.  Changing =ReactionChooserPort.choose()='s signature.
- Letting the player CHOOSE which weapon to use per reaction (e.g. "Block
  with Mace" vs "Block with Shield" as separate options).  Phase 2 auto-
  selects the best eligible weapon per reaction type.  Per-weapon player
  choice is a Phase 3 feature.

- Strike-verb weapon selection (attacking with the off-hand weapon).
- Moving shield combat stats onto =ItemResource= — =shield_patience.tres=
  stays as equipment-slot metadata only; its combat stats live on the new

func _safe_weapons(combatant) -> Array:
    var ws: Array = (
        combatant.get("weapons", []) if combatant is Dictionary

    if ws.is_empty():
        var primary: Dictionary = (
            combatant.get("weapon", {}) if combatant is Dictionary
            else combatant.weapon
        )
        return [primary]
    return ws

#+BEGIN_SRC gdscript
func _build_defense_context(target, target_action_economy) -> Dictionary:
    var weapons_list: Array = _safe_weapons(target)

    var parrying_weapon: Dictionary = _best_weapon_by(weapons_list, "parry_bonus")

Add a private helper:

#+BEGIN_SRC gdscript
## _best_weapon_by(weapons, key) -> Dictionary — returns the weapon dict
## with the highest value of `key` (ties → first wins).  Returns {} when
## `weapons` is empty.
func _best_weapon_by(weapons: Array, key: String) -> Dictionary:
    var best: Dictionary = {}
    var best_val: int = -1
    for w in weapons:
        var v: int = (w as Dictionary).get(key, 0)
        if v > best_val:
            best_val = v
            best = w as Dictionary
    return best
#+END_SRC
