#+TITLE: Iteration AA — Wizard Discharge, Frost Breath, Damage Type Logging
#+SPRINT: 38
#+VERSION: 0.2.4

* Goal

Wire the Wizard's item-discharge mechanic: a spell prepared in an equipped
item can only be cast while that item is =is_charged= (true); casting a
spell with =energy_cost > 0= discharges the item (=is_charged= → false).
Add Frost Breath — a new energy-costing spell — so this mechanic has a
real test-case.  Log damage types in the combat log for every resolved
spell hit.

* Background

Iteration Z (sprint 37) added the equipment-slot system: =ItemResource=
with =prepared_spell_id= and =is_charged=; =CharacterResource.equipped_items=;
prologue party loadouts.  The link between equipped items and the cast flow
was explicitly deferred to this iteration.

Current casting flow (summary):
- =SpellActionController.enter_selection()= calls
  =BeginCastUseCase.castable_spell_ids()=, which reads
  =actor.known_spell_ids= filtered by the round energy pool balance.
- =BeginCastUseCase.execute()= starts the cast, spending energy.
- After =remaining_actions= reaches 0, =ResolveSpellController= drives
  =ResolveCastUseCase.execute()= (rolls vs target defense, applies DAMAGE
  via =EffectsApplier=, emits a =CombatLogEntry=).

Gram Marx (Wizard) has =known_spell_ids = []= and =equipped_items= holding
=staff_gram= (=fire_bolt=, =energy_cost=0=) and =ring_channeling= (=channel=).
His spells currently come from the equipped items (Wizard paradigm) but
=BeginCastUseCase= only checks =known_spell_ids=, so Gram cannot cast
anything yet.  This iteration connects the two systems.

=CombatLogEntry= has a =damage_amount= field but no =damage_type= field;
=SpellResource= and the =Spell= domain object already carry =damage_type:
String= (e.g. ="fire"= on =fire_bolt.tres=) but it is never included in
the log entry.

The =ActionEconomy= rule object already implements =set_dazed(bool)= and
gates =combine_actions()= when dazed.  The =EffectsApplier= already
dispatches =ConditionEffect= objects to =Combatant.add_condition()=.  No
new condition infrastructure is needed — only a =condition_on_hit= trigger
on =ResolveCastUseCase=.

* Non-goals

- AoE / cone / multi-hex targeting UI — the =targeting_port.request_aoe_targets()=
  stub exists but the verb bar's Layer-2b AoE preview/confirm state is not
  implemented.  Frost Breath is **single-target** this iteration; spell
  shaping (triangle / cone shapes) is deferred.
- Resistances and vulnerability — deferred to a future sprint.  Only log
  the damage type; do not gate or modify damage amounts by it yet.
- Somatic component validation (=is_implement= gate) — already deferred
  from Iter Z; still deferred.
- Weapon damage type in the combat log — =WeaponResource.damage_type=
  exists but wiring it through the Strike log path is deferred.
- Persistent save/load of =is_charged= state — changes persist in-session
  only (Resource objects in memory).
- Rest / recharge mechanic — deferred.
- Equipment panel made editable — deferred.

*** AA-3-1  =castable_spell_ids()= includes charged equipped-item spells

After iterating =actor.known_spell_ids= (existing logic, untouched), also

list without touching his =known_spell_ids=.

*** AA-3-2  Discharge gate in =BeginCastUseCase.execute()=

In =BeginCastUseCase.execute()=: after the existing
=not actor.known_spell_ids.has(spell_id)= guard (which checks innate
known spells), add a secondary check:

If =actor.get("equipped_items", [])= contains any item with
=prepared_spell_id == spell_id= (meaning this spell is item-prepared, not
innate) AND =item.is_charged == false= → return
={success: false, error: ERR_INVALID_STATE}= (or a new error code;
mimic existing error contract shape).

If no such item exists (innate channeler spell), no charge gate applies.
This ensures Fire Bolt and Channel remain freely castable for Marigold
and Patience (they have no equipped item with those spells).

Test (unit): actor with uncharged item (=is_charged=false=) for spell_id
"frost_breath"; assert =execute()= returns =success=false=.  Actor with
charged item; assert =execute()= succeeds.  Actor with no equipped item
for the spell (Marigold's fire_bolt); assert no charge gate blocks it.

** AA-4  Daze condition on successful hit

*** AA-4-0  =ResolveCastUseCase= applies Daze on hit

In =core/application/use_cases/resolve_cast_use_case.gd=, within
=execute()='s per-target loop, after =_apply_damage_on_hit(target, attack_result)=:

If =spell.condition_on_hit == "dazed"= and =attack_result.get("hit") == true=:
construct =ConditionEffect.new(target_id, "Dazed", true)= and dispatch via
=_effects_applier.apply([condition_effect], {target_id: target})=.

The =EffectsApplier= will call =target.add_condition("Dazed")=.  The
existing =CombineActionController= already syncs
=ActionEconomy.set_dazed()= from =actor.has_condition("Dazed")= each turn,
so the combine gate is already wired — no additional changes needed there.

Test (unit): resolve a Frost Breath cast that hits; assert the target has
condition ="Dazed"=.  Resolve a Frost Breath cast that misses; assert the
target does NOT have ="Dazed"=.  Resolve a Fire Bolt hit (no
=condition_on_hit=); assert no condition is added.

* Architecture notes

- =CombatantFactory= is in =infrastructure/= (allowed to read
  =CharacterResource=); the additive ="equipped_items"= key follows the
  same flattening convention as ="known_spell_ids"=.
- =BeginCastUseCase= (=core/application/=) may read
  =actor.get("equipped_items", [])= because the combatant dict is the
  domain's own aggregate representation — this is NOT a dependency on
  =ItemResource= as a type (just duck-typed Dictionary/Resource access,
  same as all other dict key reads in the use case).
- =ResolveCastUseCase= already owns =_effects_applier= and dispatches
  =DamageEffect= objects through it; =ConditionEffect= uses the same
  dispatch path — zero new seams needed.
- =ResolveSpellController= is presentation-layer and may mutate
  =item.is_charged= directly (the item is a live Resource reference).
- =MainScene.gd= must remain at or below 1000 lines (established budget).
  No changes to =MainScene.gd= are expected for this iteration.
- All new =.tres= data files must be committed before the gate runs
  (=CLAUDE.md= commit-hygiene rule).
