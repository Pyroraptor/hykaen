** DEF-001 (CRITICAL) — on-hit Parry/Block is COSMETIC-ONLY in live play  [FEAT-212, not fixed]
round_session.gd advance_ai_turn() (~lines 1107-1167) resolves the enemy Strike via
resolve_action_use_case.resolve() with active_defense="none" — which COMMITS target.hp_current
(resolve_action_use_case.gd:335) AND emits the AttackEvent/CombatantDefeatedEvent (line 358/361) —
and only AFTER that awaits the OnHitMitigation choice, which it merely TRACES (round_session.gd
~1162-1167) without ever calling Resolution.apply_on_hit_defense(). So choosing Parry/Block reduces
damage by ZERO in live play. The two-phase TIMING (pop-up order) is correct; the on-hit MITIGATION is
not connected to the damage path. round_session.gd's own comment (~1141-1150) admits this as a
"documented interim scope limitation."

*** Correct fix (the RNG-safe two-phase REORDER — do NOT do a naive retroactive heal)
A retroactive `hp_current += mitigation` after resolve() is tempting but WRONG in the edge cases:
resolve() already emitted CombatantDefeatedEvent for a lethal-but-mitigated hit, and
Resolution.apply_on_hit_defense()'s parry/block roll must consume the use case's OWN injected RNG port
(resolve_action_use_case.gd:194's _resolution / _PortRNGAdapter), not a fresh Resolution instance, or
determinism/tests break. Instead REORDER so damage is not committed until the on-hit choice is known:
- Expose the two-phase split on resolve_action_use_case.gd (its _resolution already has resolve_to_hit()
  / apply_on_hit_defense()): e.g. resolve_to_hit_uc() (roll hit+raw damage, NO hp commit, NO event
  emit) → caller awaits the on-hit window → apply_on_hit_uc()/commit_uc() (apply the chosen defense via
  the SAME _resolution, THEN write hp_current, emit the AttackEvent with the final damage, emit
  CombatantDefeatedEvent only if still <=0). round_session.advance_ai_turn()'s Strike branch orchestrates
  those three across the two windows.
- Preserve the pinned characterization test (default/"none" path byte-for-byte) — the single-call
  resolve() stays as a thin wrapper over the three-phase path.
- Keep the ≤1-reaction budget gate (apply_on_hit spends via _try_spend_reaction; pre-hit Dodge/Steel
  already skips the on-hit window).
- This is the 189-line change AEF's FEAT-212 attempted and could not stabilize in 3 attempts (its
  partial is preserved at /tmp/FEAT212_ref_test.gd). Needs careful implementation + full GUT/pytest.
