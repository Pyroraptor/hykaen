THE KEY STRUCTURAL FACT (do not re-derive): =resolve()= / =resolve_reactive()=
call =_combatant_identifier(combatant)= → =combatant.display_id()=
(=core/application/resolve_action_use_case.gd:495,643=), so ANY combatant handed
to resolve — attacker OR reactor — MUST be a live =Combatant= instance; a dict
copy crashes there. The reactor is *dual-use*: read-only inside =reaction_window=
(reads name/conditions/conscious) BUT it is also the STRIKING combatant passed
into =resolve()= for an Opportunistic Strike — so it must stay a live instance
end-to-end, and =reaction_window= must be flipped to accept instances (a plain
=to_dict()= bridge on the reactor is WRONG — see G2).
